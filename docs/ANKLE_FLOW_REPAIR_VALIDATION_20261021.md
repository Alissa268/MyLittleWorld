# 腳踝案例：檢索修正與真實流程驗證

## 修正

1. 字面檢索沒有候選時，新增官方概念語意檢索。模型僅能將已驗證的陽性症狀與部位對應到現有官方概念；不能自行新增科別、ID、來源或病情。
2. 檢索提案再逐筆審核原文是否支持，要求 supported 與理由。審核只能刪除提案，不能擴張候選；拒絕無依據地將腫脹改成水腫、疼痛改成酸痛等性質。審核失敗不採用提案。
3. 補充官方骨科部頁面明示的「足部疼痛」概念。資料獨立放於 `backend/knowledge/supplemental_guidance_20261021.json`，保留來源、日期與既有骨科→一般骨科 canonical mapping，仍須查驗正式 DB。原始 sources.json 與 vghtpe_department_guidance.json 已核對整合前 SHA-256，內容與位元組均保留。
4. 症狀已足夠、科別仍沒有依據時，回覆科別資料不足及快速查詢途徑，不再錯回「無法產生下一題」的技術故障訊息。
5. 問題規劃 prompt 明確區分掛號導引與疾病診斷：安全已確認、科別已收斂、沒有未回答問題且有症狀細節時，建議完成，避免為補齊固定欄位而持續詢問。後端仍決定是否完成。

## 官方來源

[臺北榮民總醫院骨科部醫師／專長查詢](https://www.vghtpe.gov.tw/vghtpe/docsearch.action?more=%E9%AA%A8%E7%A7%91%E9%83%A8&q=%E8%B8%9D%E9%83%A8%E6%89%AD%E5%82%B7) 的骨科部關鍵字清單明列「足部疼痛、變形」。補充只擷取明示的足部疼痛，沒有把扭傷、骨折或其他疾病當成患者已知事實。

最初的語意檢索試作曾產生過寬的症狀對應，未列為成功驗收。最終方案加入逐筆忠實性審核，真實診斷回應已顯示拒絕「腫脹→下肢水腫」、保留有部位證據的「疼痛→足部疼痛」。這仍是模型推論，不能宣稱已取得臨床準確率。

## 可測的虛構案例

初診輸入：

> 右腳踝疼痛一星期，微微腫脹，疼痛約3分，仍可正常走路，走路沒有明顯加重，休息會減輕，沒有跌倒或扭傷。

對安全篩檢回答：

> 沒有上述任何急迫症狀。

若系統追問，依同一案例的事實補答，不指定期望科別、不修改內部狀態。實際病人應如實回答，不能照抄此虛構案例。
